# Repository notes

- This repository has planning documents and Spec Kit/OpenCode workflow scaffolding, but no application yet. The PRD's `apps/`, `packages/`, `deploy/`, and pnpm workspace are **proposed**, not present; application build/test/lint commands arrive in S-01. Recheck the tree before assuming this is still true.
- Task/checklist source: `docs/implementation-plan.md`; acceptance-case catalogue: `docs/test-cases.md`; blockers: `docs/decisions.md`. `opencode.json` loads `docs/development-workflow.md` and the Spec Kit constitution. Use `/pilot.tests`, `/pilot.implement`, `/pilot.review` for one-task handoffs; the stock `/speckit.implement` runs the feature backlog. Implementation and independent review have separate checkboxes; do not advance until both pass.
- Spec Kit is pinned to 1.0.13: `uvx --from specify-cli==1.0.13 specify check`. Feature selection uses `.specify/feature.json` or `SPECIFY_FEATURE_DIRECTORY`, not a Git branch; no Git extension is installed. Restart OpenCode after agent/command/skill/config changes.
- Prepared first batch: `/pilot.batch foundation` runs S-01's internal phases with optional disjoint parallel workers; handoff is `docs/handoffs/foundation-batch.md`. Planner-owned checks are `tests/foundation/`; preserve their recorded hashes and stop for the separate reviewer after the batch.
- Read `docs/eChallan_PRD.md` for pilot scope, priorities (P0/P1/P2), business rules, and proposed architecture; read `docs/eChallan_DESIGN.md` for tablet/admin interaction and visual rules. The PRD cites a Functional Specification v0.2 as authoritative for business rules, data fields, and open decisions, but that file is not in this repository. Do not invent its contents.
- Resolve conflicting plans before implementing the challan entry UI: PRD E2.1 requires a stepped flow, one task per screen, while the design document depicts a full-width, two-column single form. Treat neither depiction as implemented behavior.
- The PRD flags D3 (meaning of Resolved) and D5 (escalation matrix) as blockers for review/close and repeat-violation behavior; D1 (offline) and D8 (hosting/ownership) also remain open. Offline issuance is P2, not part of the P0 pilot.
- For the proposed system, `apps/api` owns the Fastify API, migrations, storage, and exports; `apps/tablet` is the marshal PWA; `apps/admin` is the dashboard; `packages/contracts` owns shared Zod contracts; `packages/theme` owns MUI tokens. The PRD calls for apps to import shared packages, never another app's internals.
- Tablet bundle constraints in the PRD: initial JS under 250 KB gzipped, exact-path MUI and icon imports, no admin-only data grid/charts/date pickers, and route-level code splitting. The design doc adds static labels above inputs, large gloved-hand touch targets, and a green filled action reserved for committing a challan.
