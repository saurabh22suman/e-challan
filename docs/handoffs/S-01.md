### R1 — clean-checkout gate order

Root cause: `pnpm -r run typecheck` uses `--noEmit` and never emits the `dist/`
declarations that `@echallan/theme` and `@echallan/contracts` point their `types`
at, so the gate was only green because of a developer's local `dist/`.

Fix, `package.json`:

```diff
-"typecheck": "pnpm -r --workspace-concurrency=1 run typecheck && pnpm run typecheck:e2e",
+"typecheck": "pnpm run build:packages && pnpm -r --workspace-concurrency=1 run typecheck && pnpm run typecheck:e2e",
```

The root script is the documented gate that both CI and the README invoke, so
making the script self-sufficient fixes the checkout and CI in one place rather
than only reordering CI steps. `README.md:99` now records the prerequisite.

Verification — a disposable workspace copy containing no `dist/`, `.env` or
`*.tsbuildinfo`, installed from the committed lockfile:

```text
python3 -m unittest tests.foundation.test_review_corrections.R1CleanArtifactGateOrder -v
  test_documented_typecheck_gate_succeeds_without_generated_artifacts ... ok
  test_documented_unit_test_gate_succeeds_without_generated_artifacts ... ok
  Ran 2 tests in 37.014s — OK
```

### R2 — app-package subpath boundaries

Root cause: `APP_PACKAGES.includes(specifier)` compares the full specifier, so a
subpath was a way around a package-level prohibition.

Fix, `tools/check-boundaries.mjs`: added `packageNameOfSpecifier()`, which
reduces a specifier to the npm package name it addresses (`@echallan/admin/src/App`
→ `@echallan/admin`) and returns `null` for a bare/unscoped specifier. The
`app-to-app-import` rule now tests that package name, so bare names, static
imports, re-exports and literal dynamic imports are all rejected regardless of
subpath. Shared-package names are unaffected, and deep shared subpaths remain
untouched as the F-01 export-map concern the planner scoped out.

### R3 — surface-specific widget restrictions

Root cause: the admin-only MUI X widget rule had no owner condition, so a
restriction declared for tablet/shared client code also blocked `apps/admin`.

Fix: added `ADMIN_ONLY_WIDGET_OWNERS = ['apps/admin']` and gated the existing
`admin-only-widget` rule on `!ADMIN_ONLY_WIDGET_OWNERS.includes(workspaceRelative)`.
Matching is on the workspace-relative package directory. Tablet and both shared
packages keep the full prohibition, bare and subpath.

R2 and R3 together:

```text
  tests.foundation.test_review_corrections.R3SurfaceSpecificWidgetRestrictions -v
```
