  `last_seen_at`, `idle_timeout_seconds`, `absolute_expires_at`, `revoked_at`;
  check on the role vocabulary and on a positive idle window; indexes on
  `user_id` and on `(revoked_at, absolute_expires_at)`.

## Test defect returned to the planner (not fixed here)

`apps/api/tests/integration/f02-auth.test.ts:353` — *"refuses a role account whose
configured username maps to a different stored role"* — cannot reach the guard it means
to test. It sets `DEMO_MARSHAL_USERNAME = 'DEMO-EMP-001'` while `DEMO_ADMIN_USERNAME` is
already `DEMO-EMP-001`, so `loadDemoCredentials` refuses the **duplicate username**
first and the request is answered 401 `invalid_credentials`. The accepted status list
includes 401, so the case passes without ever exercising the stored-role check.

- The production behaviour is correct and was verified out of band (403 `role_mismatch`
  for a unique but wrongly mapped account; 200 with a session when the guard is removed).
- A planner correction should give the role-mismatch case a **unique** username mapping,
  e.g. marshal configured as a *Supervisor's* username while the supervisor account uses
  a different one, so the refusal can only come from the role guard.
- The test was **not** edited: it is a frozen planner-owned input.

## Known issues, limitations and honest boundaries

- **Returned test defect** above; also note that `/api/challans/<unknown-id>` in the same
  file resolves to Fastify's route-level 404 rather than the handler's, so that case
  proves less than it appears to. Both are planner items.
- **Session restoration asks the server on every load.** `GET /auth/session` is called
  even with no stored token, and the server's answer alone decides what renders. That is
  what makes a reload unable to resurrect a session, but it means a brief login screen
  flash on a reload that does have a valid token.
- **A missing `DEMO_*` configuration fails closed, not loudly, on an injected app
  instance.** `server.ts` validates fatally at startup (the production path). The app
  factory returns 401 `invalid_credentials` for an unconfigured instance and logs the
  configuration error once, because a test factory that constructs an app without
  credentials must not be able to authenticate anybody.
- **No refresh workflow, no disable/reset path, no per-person attribution** (addendum A
  §4, B-08). AUTH-03's disabled-account half and AUTH-06 remain unexercised.
- **CI is not verified.** The workflow now declares the six `DEMO_*` secrets and the
  domain seed step, but hosted CI has not been run with those secrets set.
- **Browser evidence is Chromium on a desktop viewport only.** No tablet device, no
  gloved-hand check, no camera or signature hardware, no trusted HTTPS. Field
  acceptance remains an open release gate.
- The tablet idle hook was verified under a controlled clock (600 000 ms) in jsdom, not
  against a real device sleep/wake cycle.
- `docs/decisions.md` still carries no B-07/B-08 row; the register lives in the addendum

### Planner addendum (2026-10-05) — B1 causal correction

The two earlier observations above that attributed the intermittent restored-session
browser failures to reused dev servers or CPU load are **withdrawn**: neither cause was
established. The independent B1 probe in `docs/reviews/F-02-c1-implementation.md`
shows the real mechanism. Both tests navigated anonymously, wrote the token with
`page.evaluate`, then reloaded; the pending anonymous `/auth/session` refusal completed
after the storage write and the provider's no-session cleanup **cleared the externally
seeded token**, so the reloaded app correctly saw no session and showed no refusal
alert. The app behaviour is correct; the test setup was racy.

Correction (planner-owned acceptance, revision 5): both restored-role browser tests now
seed the real API-issued token with `page.addInitScript` **before the first
navigation**, preserving the role-refusal, protected-content-absence, real-token and
server-revocation assertions. No sleeps, retries or production changes. Verified 10/10
per client and 17/17 for the full browser suite.
