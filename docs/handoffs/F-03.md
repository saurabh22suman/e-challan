## Returned F-02 test defect (not fixed here)

The two F-02 browser restoration tests are intermittently flaky (~10%). **Corrected
causal explanation (2026-10-05, per review B1):** the tests seeded storage under a
running anonymous page (`page.goto` → `page.evaluate(setItem)` → `page.reload()`); the
pending anonymous `/auth/session` refusal completed after the write and the provider's
no-session cleanup cleared the externally seeded token, so the reloaded app correctly
saw no token. The earlier "Chromium propagation" explanation was **unsupported and is
withdrawn**; the independent held-response probe demonstrated storage was immediately
readable and the token was cleared by application cleanup. The app behaviour is
correct. Corrected setup: `page.addInitScript` before the first navigation, no sleeps
or retries — planner correction completed in the combined B1/M1 batch, verified 10/10
per client and 17/17 full suite. This is also why the first F-03 browser attempts
showed 16/17 before a clean run.
