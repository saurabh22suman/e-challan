## R1 — High: lookup invalidation fails on short queries and selection

Reference: `apps/tablet/src/routes/EntryFlow.tsx:166–204,215–219,235–258`.
Scope: ENT-02 and the spec's cancellation/sequence-guard requirement.

The sequence increments only after the new query is at least three characters.
Shortening a query or clearing the lookup field on selection does not invalidate
an already-running request. Its id still matches and it can update lookup state.
Cleanup cancels only the debounce timer; no AbortController/signal aborts a
started fetch, despite the handoff's cancellation claim. The short-query failure
is reproduced above on the real UI.

Planner: replace the weak timed test with manually deferred requests. First
prove the older request actually started, then test newer query, query below
threshold, clearing, selection and route/session exit. Assert no stale result
or stale error appears; cover the documented request cancellation.
Implementer: invalidate every obsolete lookup generation and cancel started
requests; treat abort as obsolete work, not a user-facing lookup failure.

## R2 — High: async validation/preview is not bound to the current draft

Reference: `EntryFlow.tsx:206–258,331–388`.
Scope: ENT-05, authoritative validation and summary integrity.

Inputs remain editable while `reviewSummary` awaits API responses. There is no
generation/snapshot check before applying them; its closure sends the original
draft but the rendered summary uses later state. A response can therefore
advance an edited, now-invalid draft. `chooseMatch` also changes material data
without using the common preview/acknowledgement invalidation path.

Planner: deterministic delayed validation **and** delayed preview cases; edit
required/summary fields or choose another registry match during each. Old
responses must not advance summary, restore a stale preview, overwrite errors
or keep an acknowledgement. Preserve valid unchanged-draft/Back controls.
Implementer: bind requests/results to a canonical draft revision, invalidate
pending reviews on material change/selection, prevent conflicting in-flight
review actions, and apply results only to their still-current draft.

## R3 — High: changed re-preview retains an old acknowledgement

Reference: `EntryFlow.tsx:378–384`;
`apps/tablet/src/__tests__/pre-issuance-repeat.test.tsx:213–237`.
Scope: REP-04/05 and spec client rule for changed re-preview.

The response replaces `preview` but never compares the old/new occurrence,
recommendation or duplicate information. The previous `acknowledged` boolean
therefore permits immediate summary for changed information. The current
re-preview test edits Remarks first, invoking material-change invalidation;
it does not test a changed server preview for an unchanged draft with an existing
acknowledgement. The independent response-order probe reproduces the bypass.

Planner: isolate unchanged draft + changed history after acknowledgement,
including changed occurrence/action and changed duplicate set/count; require
renewed acknowledgement and current summary review. Keep an unchanged-preview
control where appropriate. Implementer: invalidate acknowledgement and summary
when the server preview materially changes, even without a user field edit.

## R4 — High: F-04 layout, touch and visual constraints are incomplete

References: `EntryFlow.tsx:393–395,557–575`;
`packages/theme/src/primitives.tsx:24–35,60–74`;
`packages/theme/src/createTheme.ts:68–154`;
`packages/theme/src/touchTargets.ts:7–15`.

SPACING exports pixel values, but MUI `sx` padding and Stack spacing interpret
numbers as theme spacing multipliers. For example 48 becomes 384px and 24 becomes
192px. The measured tablet/narrow layouts consequently leave tiny fields and
large wasted space. Checkbox/label targets lack the approved tablet size/gaps.
The blue card-header treatment is absent and severity chips incorrectly use the
outlined status treatment (design §2/§6.2). Native selects also need the approved
font/size treatment rather than browser defaults.

Planner: measure the **form/card** usable width and spacing at representative
tablet/narrow widths and 200% zoom, not merely “no horizontal overflow”; cover
all interactive control types and adjacent target gaps. Distinguish solid labelled
severity from outlined labelled status and reserve green fill for commitment.
Assert blue header treatment and readable input typography. The entry test's
location comment at `pre-issuance-entry.test.tsx:242–243` only asserts absence of
an editable input, not positive read-only context display. Require accurate
session-bound context display; the summary currently labels a post code as Location.

Implementer: use a consistent spacing-unit convention, apply the approved
touch/typography/card/chip rules and accurate context labels. Keep the full-width
single-form flow and avoid fabricated navigation destinations or totals.

## R5 — Medium: API errors can be invisible; catalogue contracts are bypassed

References: `EntryFlow.tsx:100–114,145–155,323–329,535–589`;
`apps/api/src/preIssuance/service.ts:250–258`.

The server's Other field identifiers are department/vehicleType/contractor/
violationType. `applyServerErrors` stores those verbatim, while controls read
departmentId/vehicleTypeId/contractorId/violationTypeIds and remarks. The valid
Other-error probe consequently blocks silently. Unmapped draft/registry errors
also need an accessible fallback instead of disappearing.

`toOptions` is an ad-hoc shape cast, not `MasterListResponseSchema` validation.
Malformed/incorrect-kind successful catalogues can become empty or incomplete
options without the explicit failure state. Some repeat fixtures themselves
omit required violation severity/defaultAction (repeat test catalogue at 55–61),
so they must be corrected to the reviewed F-03 wire contract before proper client
parsing is introduced.

Planner: authoritative 422 Other/context/generic errors with visible associated
feedback, and malformed/wrong-kind catalogue controls with recoverable errors.
Use genuinely contract-valid master fixtures across new and reconciled suites.
Implementer: map semantic errors to their actual controls, supply an alert
fallback, and consume shared catalogue contracts with expected-kind checks.
