Load the pilot-tdd skill. Read the task in docs/implementation-plan.md, its test
cases in docs/test-cases.md, and docs/decisions.md. Resolve dependencies first.
Create/update the task's bounded Spec Kit feature and acceptance tests; do not
implement production behaviour. For scaffolding, define smoke checks instead.
Record RED evidence or precisely explain what harness is still missing. Hand
off only the requested task with paths, commands, fixtures, and acceptance IDs.
Do not silently approve unresolved business decisions or review your own code.
